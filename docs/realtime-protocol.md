# 실시간 서버 메시지 규약 (v0.16)

프론트엔드(`frontend/src/net/`)와 realtime-server가 주고받는 WebSocket 메시지 규약입니다. 양쪽은 이 문서만 보고 개발합니다. 메시지 형식을 바꾸면 프로토콜 버전 `v`를 올립니다.

> 상태: **정책 대부분 확정**. 아직 남은 결정은 문서 끝 [미결정 항목](#미결정-항목)에 있습니다.

## 1. 연결

| 항목 | 값 |
|---|---|
| 주소 | `wss://<api 도메인>/ws` (로컬 개발: `ws://localhost:8080/ws`) |
| 프레임 | 텍스트 프레임, UTF-8 JSON 한 개 |
| 공통 필드 | 모든 메시지에 `type`. 응답이 필요한 요청에는 `reqId` (클라이언트가 만든 문자열) |
| 최대 메시지 크기 | 2 KB. 넘으면 연결 종료 `4005` |
| 허용 Origin | `https://gohaeyaji.com`, `https://www.gohaeyaji.com`, `https://hae-gun.github.io`(도메인 이전 기간), `http://localhost:5173`. 그 외는 핸드셰이크 거절 |
| 인증 | 없음. 익명 세션만 사용 |
| IP당 동시 연결 | 최대 20개. 넘으면 `4004` (학교, 회사처럼 IP 하나를 여럿이 쓰는 환경 고려) |

> Origin은 경로를 포함하지 않으므로 `hae-gun.github.io` 아래의 다른 Pages 사이트도 통과합니다. 프론트가 `gohaeyaji.com`으로 옮겨 가고 예전 주소가 새 도메인으로 넘어가는 것을 확인하면 github.io는 목록에서 뺍니다.

## 2. 채널 정책

| 항목 | 값 |
|---|---|
| 채널당 고해소 | 21칸 고정 (v0.8, 고해소 방의 왼쪽, 앞, 오른쪽 벽에 7칸씩. v0.7까지는 20칸) |
| 채널 정원 | 100명 (하드 리밋, v0.14. 이전 60명) |
| 신규 배정 기준 | 접속자가 80명(정원의 80%) 미만인 채널 중 번호가 가장 작은 곳 |
| 새 채널 생성 | 모든 채널이 80명 이상이면 다음 번호 채널을 만든다 |
| 남은 20% (49~60번째 자리) | 재접속(`resumeToken`)으로 돌아오는 사람 전용. 신규 배정에는 쓰지 않음 |
| 채널 정리 | 1채널을 뺀 채널이 접속자 0명으로 5분 지나면 닫음(v0.10, 서버 하트비트가 처리). 번호는 작은 것부터 재사용. 그래서 채널 수는 가장 붐볐던 순간에 필요했던 만큼을 넘지 않고, 사람이 빠지면 다시 줄어듦 |
| 직접 옮기기 | 열려 있는 채널로 직접 옮길 수 있음(v0.10, 18장). 이때는 80%가 아니라 정원 100명까지 |
| 앞 채널 다시 채우기 | 1채널이 80명 아래로 내려가면 신규 접속자는 다시 1채널로 |
| 서버 전체 한도 | 부하테스트로 정함. 넘으면 `busy` 응답 후 5초마다 자동 재시도 (대기열은 6단계 이후) |

## 3. 전체 흐름

```
클라이언트                                   서버
   │ ── WebSocket 연결 ─────────────────────▶ │
   │ ── hello ──────────────────────────────▶ │  버전 확인, 세션 발급 또는 복구, 채널 배정
   │ ◀────────────────────────────── welcome ─ │  채널 번호 + 고해소 상태 + 줄 길이
   │ ── ping (10초마다) ────────────────────▶ │
   │ ◀───────────────────────────────── pong ─ │
   │ ◀──────────────────────── booth (변경분) ─│  같은 채널 누군가 입장, 퇴장, 예약
   │                                          │
   │ ── claim {boothId} ────────────────────▶ │  Redis 잠금 시도
   │ ◀──────────────────── claimResult ────── │  성공한 사람만 문 열림 애니메이션
   │ ── activity (입력 중, 최대 5초에 1번) ─▶ │  무입력 타이머 리셋
   │ ── release ────────────────────────────▶ │
   │ ◀──────────────────────────── released ─ │
```

방이 모두 찼을 때:
```
   │ ── queueJoin ──────────────────────────▶ │  채널 줄 맨 뒤에 서기
   │ ◀─────────────── queueResult {position} ─ │
   │ ◀──────────────────── queue {position} ── │  앞사람이 빠질 때마다
   │                       (누군가 퇴장)       │  빈 방을 맨 앞사람에게 20초간 예약
   │ ◀──────────── queueCall {boothId, holdUntil} │
   │ ── claim {boothId} ────────────────────▶ │  예약자만 성공
```

## 4. 고해소 상태

| state | 뜻 | LED |
|---|---|---|
| `free` | 비어 있음 | 꺼짐 |
| `occupied` | 누군가 고해 중 | 빨간색 |
| `reserved` | 줄 맨 앞사람을 위해 맡아둔 방 (최대 20초) | 노란색 깜빡임 (다른 사람이 E를 누르면 "예약된 고해소입니다") |

## 5. 클라이언트 → 서버

### hello
연결 직후 1회. 이 메시지 전에는 다른 메시지를 보낼 수 없습니다.
```json
{ "type": "hello", "v": 1, "resumeToken": "rt_...", "name": "성실한 토마스", "client": { "app": "web", "version": "0.2.0" } }
```
- `v`: 프로토콜 버전. 서버가 지원하지 않으면 `4001`로 종료
- `resumeToken`: 재접속일 때만. 유효하면 같은 세션, 점유 중이던 방, 줄 순번을 복구
- `face` (v0.5): 이 브라우저가 기억하는 내가 그린 얼굴(15장). 형식이 틀리면 조용히 기본 얼굴
- `name` (v0.4): 이 브라우저가 기억하는 내 이름. 없거나 검사(14장)를 통과하지 못하면 서버가 무작위 세례명을 줌. 거절 사유는 알리지 않음

### ping
```json
{ "type": "ping", "t": 1793380000000 }
```

### claim
```json
{ "type": "claim", "reqId": "r12", "boothId": 3 }
```

### release
```json
{ "type": "release", "reqId": "r13", "boothId": 3, "reason": "USER" }
```
- `reason`: `USER` (나가기 버튼) 또는 `IDLE` (프론트 카운터가 0이 되어 스스로 나감)

### activity
고해소 안에서 타이핑하거나 고해를 보냈다는 신호. 무입력 타이머를 리셋합니다. **최대 5초에 1번**만 보냅니다.
```json
{ "type": "activity" }
```

### move
내 위치. **움직이는 동안만** 최대 초당 5번(200ms 간격), 멈추면 마지막 위치를 1번 더 보냄. 고해소 안에서는 보내지 않음.
```json
{ "type": "move", "x": -1.75, "z": 12.4, "ry": 3.14 }
```
- `x`, `z`: 바닥 좌표(m), `ry`: 바라보는 방향(라디안). 소수 둘째 자리까지
- 서버는 직전 move 후 150ms가 안 지났으면 버림(지연 흔들림 허용치 포함). 범위를 벗어나면 맵 경계로 자름(v0.15: x -40..55, z -75..112. 넓어진 본당과 성당 둘레길, 산책로, 이벤트 광장까지)
- 처음 move를 보내기 전까지는 다른 사람에게 보이지 않음 (인트로 화면에 머무는 사람은 복도에 안 나타남)

### rename (v0.4)
내 이름 바꾸기. 결과는 `renameResult`.
```json
{ "type": "rename", "reqId": "r9", "name": "고해왕 베드로" }
```
- 검사 규칙은 14장. 바뀐 이름은 다음 `presence` 묶음의 `named`로 채널 전원에게 전달

### setFace (v0.5)
내가 그린 얼굴 쓰기. 결과는 `faceResult`.
```json
{ "type": "setFace", "reqId": "r10", "face": "0000...0110...(1024자)" }
```
- `face`: 16x16 그림, 15장 형식. `null`이면 기본 얼굴로 돌아감
- 바뀐 얼굴은 다음 `presence` 묶음의 `faced`로 채널 전원에게 전달

### report (v0.6)
같은 채널에서 다른 사람이 쓰고 있는 그린 얼굴을 신고. 결과는 `reportResult`.
```json
{ "type": "report", "reqId": "r11", "pid": 21 }
```
- 신고 대상은 사람이 아니라 그 순간의 그림. 그림을 바꾸면 새 그림은 0부터 다시 셈

### inquiry (v0.8)
고해소 방 가운데 "신께 알리기" 함에 남기는 사이트 문의. 답은 `inquiryResult`.
```json
{ "type": "inquiry", "reqId": "q3", "kind": "bug", "text": "고해소 문이 가끔 안 열려요" }
```
- `kind`: `question`(질문), `request`(문의), `idea`(제안), `bug`(오류 신고)
- `text`: 5~500자. 줄바꿈은 남기고 제어 문자는 지움. 빈 줄은 두 줄까지만
- 17장 참고

### emote (v0.7)
동작 시작. 답은 없음(보낸 사람은 이미 화면에서 재생 중).
```json
{ "type": "emote", "id": "hooray" }
```
- `id`: `pray`(4초), `cross`(4.6초), `hooray`(3.6초), `doze`(5초), `praise`(4.8초, v0.18 찬양: 팔을 들고 흔들며 "라랄라~" 흥얼거림)
- `sit`(v0.9): 벤치나 장의자에 앉기. 좌석 위치를 같이 보냄 `{ "type": "emote", "id": "sit", "x": 3.95, "z": 1.48, "ry": 3.14 }`. 서버는 그 위치를 그대로 쓰고(직전 move가 레이트리밋에 걸렸어도 자리가 맞게) 같은 묶음에 `moved`와 `emoted`로 알림
- 서버는 앞 동작이 끝나기 전(0.3초 여유)이거나, 모르는 id이거나, 고해소 안이면 조용히 버리고 `gohaeyaji_emotes_dropped_total`만 올림
- 받아들인 동작은 다음 `presence` 묶음의 `emoted`로 채널 전원에게 전달

### queueJoin
모든 고해소가 `occupied` 또는 `reserved`일 때만 가능.
```json
{ "type": "queueJoin", "reqId": "r20" }
```

### queueLeave
```json
{ "type": "queueLeave", "reqId": "r21" }
```

### resync
`seq`가 건너뛰었을 때 전체 상태 다시 요청.
```json
{ "type": "resync" }
```

### confess (7단계, 답변 엔진 서버 이전 후)
```json
{ "type": "confess", "reqId": "r14", "boothId": 3, "text": "어제 밤새 쇼츠만 봤어요" }
```
- `text` 최대 200자. 서버는 원문을 저장하거나 로그에 남기지 않음

## 6. 서버 → 클라이언트

### welcome
```json
{
  "type": "welcome",
  "v": 1,
  "sessionId": "s_8f2c...",
  "resumeToken": "rt_...",
  "channelNo": 3,
  "boothCount": 21,
  "booths": { "occupied": [0, 4, 7], "reserved": [12] },
  "queueSize": 5,
  "seq": 1042,
  "heartbeatMs": 10000,
  "idle": { "limitMs": 90000, "warnMs": 20000, "dangerMs": 10000 },
  "you": { "pid": 17, "name": "베드로" },
  "players": [[3, -1.2, 14.5, 3.1, -1], [9, 1.75, -8.0, 1.57, 12]],
  "names": [[3, "마르타"], [9, "성실한 토마스"], [17, "베드로"]],
  "faces": [[9, "0000...(1024자)"]],
  "sitting": [9],
  "presenceMs": 200,
  "serverTime": 1793380000123
}
```
- 복구된 세션이면 `"resumed": { "boothId": 3 }` 또는 `"resumed": { "queuePosition": 4 }` 추가
- `idle`: 무입력 퇴장 설정. 프론트는 이 값으로 카운터를 그림 (7장)
- `you.pid`: 이 채널에서 나를 가리키는 짧은 번호. 위치 메시지는 세션 ID 대신 pid를 씀
- `players`: 지금 보이는 다른 사람들 `[pid, x, z, ry, 고해소 번호(없으면 -1)]`. 고해소 안에 있는 사람은 화면에서 숨김
- `faces` (v0.5): 얼굴을 그린 사람만 `[pid, 그림]`
- `you.name`, `names` (v0.4): 내 이름과 채널 전원의 이름 `[pid, 이름]`. v0.16부터 세 번째 칸에 모습 `[pid, 이름, "m"|"f"]`(형제님, 자매님). 아직 안 보이는(첫 move 전) 사람도 포함. 클라이언트는 `you.name`을 기억했다가 다음 `hello`에 보냄
- `presenceMs`: 위치 묶음이 오는 간격 (13장)

### pong
```json
{ "type": "pong", "t": 1793380000000, "serverTime": 1793380000150 }
```

### booth
같은 채널의 고해소 상태가 바뀔 때마다 채널 전원에게.
```json
{ "type": "booth", "ch": 1, "boothId": 3, "state": "occupied", "seq": 1043, "pid": 17 }
```
- `pid`: 들어간 사람 (v0.3). 클라이언트는 그 사람의 캐릭터를 숨기고, 이 방이 `free`가 되면 다시 보여줌
- `seq`는 채널별로 1씩 증가. 건너뛰면 클라이언트가 `resync` 요청
- `ch` (v0.10): 채널 번호. 채널을 막 옮긴 클라이언트는 예전 채널 것이 늦게 오면 버림

### presence
같은 채널의 위치 변화를 **200ms마다 한 묶음으로** 채널 전원에게 (13장). 바뀐 게 없으면 보내지 않음.
```json
{ "type": "presence", "ch": 1, "t": 1793380000400, "moved": [[3, -1.0, 14.1, 3.1], [21, 0.4, 28.9, 0.0]], "left": [9], "named": [[21, "루치아"]] }
```
- `moved`: 그 사이 움직인 사람 `[pid, x, z, ry]`. 처음 보는 pid면 새로 나타난 사람
- `left`: 채널을 떠난 사람(연결 종료). 화면에서 제거
- `named` (v0.4): 그 사이 들어왔거나 이름을 바꾼 사람 `[pid, 이름]`. 없으면 필드 자체가 빠짐
- `faced` (v0.5): 그 사이 들어오면서 그린 얼굴을 가져왔거나 얼굴을 바꾼 사람 `[pid, 그림]`. 빈 문자열이면 기본 얼굴로 돌아감. 없으면 필드가 빠짐
- `emoted` (v0.7): 그 사이 시작된 동작 `[pid, id]`. 받은 클라이언트는 그 사람 캐릭터에서 처음부터 재생. 지나간 동작은 다시 보내지 않음(늦게 들어온 사람은 못 봄)
- 내 pid도 들어올 수 있음. 클라이언트는 무시
- 위치나 이름이 하나라도 바뀌었을 때만 보냄

### renameResult (v0.4)
```json
{ "type": "renameResult", "reqId": "r9", "ok": true, "name": "고해왕 베드로" }
{ "type": "renameResult", "reqId": "r9", "ok": false, "name": "진 신부님", "reason": "RESERVED" }
```
- `name`: 서버가 정리한 이름(앞뒤 공백 제거, 연속 공백 하나로). 성공이면 이 이름을 기억
- `reason`: `INVALID`(길이, 글자 종류) / `BLOCKED`(금지어) / `RESERVED`(사칭) / `TOO_SOON`(10초 안에 다시 바꿈)

### faceResult (v0.5)
```json
{ "type": "faceResult", "reqId": "r10", "ok": true }
{ "type": "faceResult", "reqId": "r10", "ok": false, "reason": "TOO_SOON" }
```
- `reason`: `INVALID`(형식이 틀림) / `TOO_SOON`(5초 안에 다시 바꿈) / `BLOCKED`(v0.6: 신고로 내려간 그림이거나, 내 그림이 내려간 뒤 10분 동안)

### inquiryResult (v0.8)
```json
{ "type": "inquiryResult", "reqId": "q3", "ok": true }
{ "type": "inquiryResult", "reqId": "q3", "ok": false, "reason": "TOO_SOON" }
```
- `reason`: `INVALID`(종류나 길이) / `TOO_SOON`(1분 안에 다시) / `TOO_MANY`(같은 IP에서 1시간에 10건 넘음)

### reportResult (v0.6)
```json
{ "type": "reportResult", "reqId": "r11", "ok": true }
{ "type": "reportResult", "reqId": "r11", "ok": false, "reason": "ALREADY" }
```
- `reason`: `NO_FACE`(그린 얼굴을 안 쓰는 사람, 없는 pid) / `SELF` / `ALREADY`(이 그림을 이미 신고함) / `TOO_MANY`(1분에 10번 초과)
- 몇 명이 신고했는지는 알려 주지 않음

### faceRemoved (v0.6)
내 그림이 신고로 내려갔을 때 나에게만.
```json
{ "type": "faceRemoved", "reason": "REPORTED", "blockedMs": 600000 }
```
- 클라이언트는 기본 얼굴로 돌아가고 기억해 둔 그림도 지움. `blockedMs` 동안 `setFace`는 `BLOCKED`

### snapshot
`resync` 응답 또는 서버 판단으로 전체 상태 재전송.
```json
{ "type": "snapshot", "booths": { "occupied": [0, 4, 7], "reserved": [12] }, "queueSize": 5, "seq": 1043 }
```

### queueSize
줄 길이가 바뀔 때 채널 전원에게 (복도에 "대기 5명" 표시용). 1초에 최대 1번으로 묶어서 보냄.
```json
{ "type": "queueSize", "size": 5 }
```

### claimResult
```json
{ "type": "claimResult", "reqId": "r12", "boothId": 3, "ok": true, "leaseMs": 30000 }
```
```json
{ "type": "claimResult", "reqId": "r12", "boothId": 3, "ok": false, "reason": "OCCUPIED" }
```
| reason | 뜻 | 클라이언트 처리 |
|---|---|---|
| `OCCUPIED` | 다른 사람이 먼저 들어감 | "고해성사가 진행중입니다" 안내 |
| `RESERVED` | 줄 선 사람을 위해 예약된 방 | "줄을 선 분을 위해 비워둔 고해소입니다" 안내 |
| `ALREADY_IN_BOOTH` | 이 세션이 이미 다른 방에 있음 | 무시 |
| `INVALID_BOOTH` | 없는 번호 | 버그로 기록 |
| `RATE_LIMITED` | 너무 자주 시도 | 잠시 후 다시 안내 |

### released
```json
{ "type": "released", "boothId": 3, "reason": "IDLE" }
```
| reason | 뜻 | 클라이언트 처리 |
|---|---|---|
| `USER` | 내가 나감 | 복도로 |
| `IDLE` | 무입력 90초 | "오랫동안 입력이 없어 나왔습니다" 후 복도로 |
| `LEASE_EXPIRED` | 하트비트 끊김으로 임대 만료 | 복도로, 재접속 |

### queueResult
```json
{ "type": "queueResult", "reqId": "r20", "ok": true, "position": 5, "size": 5 }
```
| reason (ok=false) | 뜻 |
|---|---|
| `BOOTHS_AVAILABLE` | 빈 방이 있음. 줄 설 필요 없음 |
| `ALREADY_QUEUED` | 이미 줄에 있음 |
| `IN_BOOTH` | 고해소 안에 있음 |

### queue
내 순번이 바뀔 때 (줄 선 사람에게만).
```json
{ "type": "queue", "position": 2, "size": 9 }
```

### queueCall
내 차례. 방을 20초간 맡아둠. 프론트는 안내를 띄우고 그 방까지 자동으로 걸어가게 할 수 있음.
```json
{ "type": "queueCall", "boothId": 7, "holdUntil": 1793380020000 }
```

### queueMissed
20초 안에 들어가지 않아 줄에서 빠짐. 예약은 다음 사람에게 넘어감.
```json
{ "type": "queueMissed", "boothId": 7 }
```

### answer (7단계)
```json
{ "type": "answer", "reqId": "r14", "kind": "answer", "line": "...", "penance": "...", "voiceId": "dopamine-pen-02" }
```
- `kind`: `answer` | `safety` | `blocked` | `tooShort`

### busy
서버 전체 한도 초과로 채널을 배정할 수 없음. 연결은 유지하고 클라이언트가 5초 뒤 `hello` 재시도.
```json
{ "type": "busy", "retryAfterMs": 5000 }
```

### notice
```json
{ "type": "notice", "code": "MAINTENANCE", "message": "5분 뒤 점검이 시작됩니다", "at": 1793380300000 }
```

### error
```json
{ "type": "error", "reqId": "r12", "code": "BAD_MESSAGE", "message": "boothId is required" }
```
| code | 뜻 |
|---|---|
| `BAD_MESSAGE` | JSON이 아니거나 필수 필드 누락 |
| `NOT_READY` | hello 전에 다른 메시지 |
| `UNKNOWN_TYPE` | 모르는 `type` |
| `RATE_LIMITED` | 레이트리밋 초과 |

## 7. 무입력 퇴장

| 항목 | 값 |
|---|---|
| 퇴장 시간 | 마지막 활동 후 90초 |
| 활동으로 인정 | 입장(claim 성공), 타이핑, 고해 전송, 신부 답변 표시 완료 |
| 노란색 카운터 | 남은 시간 20초부터 (입력 없이 70초 경과) |
| 빨간색 카운터 | 남은 시간 10초부터 (입력 없이 80초 경과) |
| 성호경과 답변 대기 중 | 타이머 멈춤. 신부가 말하는 동안 사용자가 쫓겨나지 않게 |

역할 분담:
- **프론트가 주인**: 카운터 표시와 90초 퇴장은 프론트가 자기 시계로 정확히 처리하고 `release {reason: IDLE}`를 보냄
- **서버는 안전망**: 마지막 `activity` 후 100초(90초 + 여유 10초)가 지나도 release가 없으면 서버가 회수하고 `released {reason: IDLE}`. 브라우저가 멈췄거나 조작된 경우 대비
- `activity`를 최대 5초에 1번만 보내므로, 서버가 보는 마지막 활동은 실제보다 최대 5초 늦음. 여유 10초가 이 차이를 덮음

## 8. 줄서기

| 항목 | 값 |
|---|---|
| 줄 단위 | 채널마다 한 줄 (방마다 따로 서지 않음) |
| 순서 | 먼저 선 사람 먼저 (FIFO) |
| 설 수 있는 때 | 모든 방이 `occupied` 또는 `reserved`일 때 |
| 차례가 오면 | 빈 방을 `reserved`로 바꾸고 20초간 맡아둠 (`queueCall`) |
| 20초 안에 안 들어오면 | 줄에서 빠짐 (`queueMissed`), 다음 사람 호출 |
| 줄 선 상태에서 | 복도를 자유롭게 돌아다닐 수 있음 |
| 연결이 끊기면 | 15초 유예 동안 순번 유지, 그 뒤 줄에서 빠짐 |
| 방이 비는 순간 | "해제, 다음 사람 꺼내기, 예약"을 Redis Lua 스크립트 하나로 원자적으로 처리 |

| 코드 | 이름 | 클라이언트 처리 |

### 재접속 규칙
- 지수 백오프: 1초, 2초, 4초, 8초 ... 최대 30초, 매번 0~1초 랜덤 지연 추가
- `hello`에 `resumeToken` 포함. 15초 안이면 방과 줄 순번 복구
- 재접속 중에는 "다시 연결하는 중" 표시, 고해 입력 잠금

## 14. 이름 (v0.4)과 모습 (v0.16)

모습: `hello.look`으로 시작하고, `{ "type": "setLook", "look": "f32" }`로 바꿈. 모습 값은 옷 한 글자("m" 형제님, "f" 자매님) 뒤에 피부색과 머리 모양 번호(0..4)를 붙인 코드. 피부색은 기본 색 번호 한 자리(0..5)나 직접 고른 RGB 색 16진수 여섯 자리(소문자). 정규식 `^[mf]((?:[0-5]|[0-9a-f]{6})[0-4])?$`, 예 "f32" = 자매님, 피부색 3, 머리 모양 2, "mc98d5f4" = 형제님, 피부색 #c98d5f, 민머리. 머리 모양 4는 형제님과 자매님 모두 민머리. "m", "f" 한 글자만 오면 기본 피부색(1)과 머리 모양(0). 없거나 잘못되면 "m"(응답 없음, 1초에 1회, 잘못된 값은 버림). 바뀌면 다음 `presence.named`에 이름과 함께 `[pid, 이름, 모습]`으로 나가고, `welcome.names`에도 같은 형태로 들어감. 예전 화면은 세 번째 칸을 무시하므로 v는 1 그대로.

| 항목 | 값 |
|---|---|
| 처음 이름 | 서버가 세례명 목록(`saint-names.txt`, 약 90개)에서 무작위. 중복 허용(pid로 구분) |
| 기억 | 브라우저 localStorage(`gohaeyaji-name`). 다음 접속 때 `hello.name`으로 보냄 |
| 바꾸기 | `rename`. 성공한 변경 기준 10초에 1회 |
| 규칙 | 2~10자, 한글 음절, 영문, 숫자, 단어 사이 공백 한 칸. 자음만(ㅋㅋ), 기호, 이모지 불가 |
| 사칭 금지 | 신부, 사제, 주교, 교황, 수녀, 하느님, 예수, 관리자, 운영, admin 등 (`NameService.RESERVED`). 공백을 빼고 검사 |
| 금지어 | 브라우저와 같은 비공개 `blocked.json`을 서버가 읽음(`gohaeyaji.blocked-words-file`, 환경 변수 `BLOCKED_WORDS_FILE`). 공백, 기호를 빼고 소문자로 비교 |
| 표시 | 다른 사람의 이름은 3m 안에 있을 때만 머리 위에. 고해소 안에서는 안 보임. 내 이름은 상단 버튼에 |
| 검사 위치 | 서버가 최종 판단. 브라우저는 같은 기본 규칙(금지어 제외)으로 즉시 안내만 |

## 15. 그린 얼굴 (v0.5)

| 항목 | 값 |
|---|---|
| 형식 | 32x32 칸을 왼쪽 위부터 줄 순서로 1024자(v0.6, v0.5는 16x16). 칸마다 글자 하나: 0 빈칸(피부가 보임), 1 검정, 2 빨강, 3 흰색, 4 분홍, 5 6 7 8 9 a b c 직접 고른 색 1~8번(v0.12, v0.8은 5 하나). 메시지 한도 2KB 안에 들어감 |
| 직접 고른 색 (v0.12) | 그림 하나에 최대 8가지. 하나라도 쓰면 격자 뒤에 `:rrggbb,rrggbb,...`(고른 색 순서대로). 같은 그림이 늘 같은 코드가 되게 정규화: 안 쓴 색은 빼고, 쓴 색만 5부터 차례로 번호를 다시 매김(브라우저 `joinFace`, 서버 `FaceRules.normalize`가 같은 규칙). 서버는 격자가 쓰는 색 번호보다 색이 적으면 거절하고, 색은 소문자로 저장. 한 색을 바꾸면 그 색으로 찍은 점이 모두 바뀜. 해시와 신고는 정규화한 코드 기준. 예전(v0.8) `:rrggbb` 하나짜리 그림도 그대로 유효 |
| 예전 그림 | 브라우저에 남은 16x16 그림은 칸마다 2x2로 늘려 32x32로 바꿔 씀. 서버는 32x32만 받음 |
| 붓 | 가는 붓(1칸), 굵은 붓(2x2, 기본) |
| 그릴 수 있는 것 | 머리 앞면의 얼굴만. 정해진 다섯 가지 색과 직접 고른 색 최대 여덟 가지. 머리카락, 피부, 몸은 못 그림 |
| 기본 얼굴 | 다 지운 그림은 `null`로 보냄. 서버도 0만 있는 그림은 기본 얼굴로 처리 |
| 기억 | 브라우저 localStorage: 지금 쓰는 얼굴(`gohaeyaji-face`), 예전에 그린 얼굴 최대 12개(`gohaeyaji-face-gallery`). 다시 접속하면 `hello.face`로 보냄 |
| 보이는 곳 | 내 캐릭터와, 다른 사람 화면의 내 캐릭터. 생성된 표정 대신 그린 얼굴을 2배로 키워 붙임 |
| 보지 않기 | "다른 사람이 그린 얼굴 보기"를 끄면 남의 그림 대신 기본 얼굴(브라우저 설정, `gohaeyaji-show-drawn`) |
| 숨기기 (v0.6) | 이름표(그린 얼굴을 쓰는 사람은 ✎ 표시)를 누르면 메뉴. "이 얼굴 숨기기"는 그 그림을 내 화면에서만 기본 얼굴로. 그림 내용의 해시로 기억해서 다음 접속에도 숨겨짐(`gohaeyaji-face-hidden`, 최대 200개). 신고한 그림도 자동으로 숨김 |
| 신고 (v0.6) | 그림(SHA-256 앞 16바이트) 기준으로 Redis에 신고한 세션 집합(`gy:face:{hash}:reports`, 1시간). 서로 다른 3세션이 신고하면 그 그림을 24시간 금지(`gy:face:{hash}:ban`, 원자적으로 한 번만, `report_face.lua`). 그 그림을 쓰던 사람은 기본 얼굴로 돌아가고 `faceRemoved`를 받으며 10분 동안 얼굴을 못 바꿈. 금지된 그림은 `hello.face`, `setFace` 모두 거절 |
| 검사 | 서버는 형식(길이, 글자 0~9 a~c, 색 표기)과 금지 목록만 검사. 그림 내용은 자동으로 거를 수 없어서 신고와 숨기기로 대응 |
| 지표 | `gohaeyaji_face_reports_total`, `gohaeyaji_face_bans_total` |
| 관리자 페이지 | `/admin`(Spring 안, HTTP Basic 로그인, 비밀번호 `ADMIN_PASSWORD`가 없으면 페이지 자체가 없음). 신고된 그림은 원본과 기록을 7일 보관(`gy:face:{hash}:data`, `:record`, 목록 `gy:admin:faces`). 관리자가 24시간 금지, 영구 금지(만료 없음), 돌려주기(금지와 신고 기록 삭제), 삭제(그림과 기록과 IP를 모두 지움, 금지는 유지) 가능. 금지하면 지금 쓰는 사람에게서도 바로 내림 |
| 신고 내역 | 신고마다 시각, 채널, 신고한 사람의 이름과 IP, 신고된 사람의 이름과 IP를 그림별로 최대 50건(`gy:face:{hash}:log`). 그림과 같이 7일 뒤 또는 삭제할 때 지워짐(영구 금지한 그림은 기록도 유지). IP는 개인정보라 출시 전 개인정보 처리방침에 보관 목적과 기간을 적어야 함. 배포 때 Caddy 뒤에서도 실제 IP가 남도록 X-Forwarded-For를 신뢰하는 설정(`forward-headers-strategy: native`) 유지 |
| 한계 | 신고 대상 찾기는 같은 서버에 붙은 사람만(6단계에서 Redis로). 세션을 새로 열면 신고를 다시 할 수 있어서, IP당 연결 20개 제한이 사실상의 상한 |
| 서버 여러 대 | 위치, 이름과 같음. 6단계에서 Redis Pub/Sub로 확장 |

## 16. 동작 (v0.7)

| 항목 | 값 |

## 17. 성당 안과 신께 알리기 (v0.8)

| 항목 | 값 |
|---|---|
| 구성 | 정문으로 들어가면 입구 홀(성수대, 바닥 별 무늬 위 안내 표지판: 앞 본당, 오른쪽 고해소), 그 뒤로 본당(장의자, 제대, 촛불대, 봉헌함). 입구 홀 오른쪽 끝 옆문으로 고해소 방. 고해소 방은 들어서서 왼쪽 벽 1~7번, 앞 벽 8~14번, 오른쪽 벽 15~21번 |

## 19. 답변 개선함 (v0.11)

고해 내용은 기본적으로 어디에도 저장하지 않는다. 사람이 직접 동의하고 보낸 것만 예외.

| 항목 | 값 |
|---|---|
| 화면 | 신부님 답(일반 답변과 일상 대화) 아래 "답이 엉뚱해요" 버튼. 위기 답변(safety), 금지어, 너무 짧은 입력에는 없음. 서버 연결 때만 |
| 동의 | 누르면 창이 열림: 무엇을 보내는지(고해와 신부님 답), 어디에 쓰는지(답변 고치기), 언제 지우는지(30일), 무엇을 안 보내는지(이름, IP), 가리는 것(전화번호, 이메일, 긴 숫자). 보낼 고해는 보내기 전에 고칠 수 있음. "동의하고 보내기"를 눌러야만 전송 |
| 메시지 | `{ "type": "feedback", "reqId": "r2", "reason": "wrong", "text": "...", "persona": "jin", "category": "generic", "answer": "..." }` -> `{ "type": "feedbackResult", "reqId": "r2", "ok": true }`. `reason`: `wrong`(주제를 잘못 알아들음), `bland`(너무 뻔함) |
| 서버 검사 | 고해소 안에서만, 고해 1~200자, 답 800자까지, 신부님과 카테고리 형식, 10초에 한 번, IP당 1시간 30건(IP 해시로만 셈). 저장 전에 전화번호, 이메일, 긴 숫자를 한 번 더 가림 |
| 실패 이유 | `INVALID`, `TOO_SOON`, `TOO_MANY` |
| 관리자 페이지 | "답변 개선함": 할 일, 카테고리 잘못, 새 주제, 무시로 분류, 삭제. "AI에 넘길 내용 만들기"는 answers.json 형식 설명, 톤, 표시한 고해 목록을 한 번에 복사. API `GET /admin/api/feedback`, `POST /admin/api/feedback/{id}/mark/{todo|wrong|new|ignore}`, `POST /admin/api/feedback/{id}/delete` |
| 반영 | 지금은 AI가 준 JSON을 answers.json에 넣고 다시 배포. 답변 엔진을 서버로 옮기면(7단계) 관리자 페이지에서 바로 반영하고 되돌릴 수 있게 할 예정 |

## 20. 이용 통계 (v0.19)

어디서 빠지고 무엇에 반응하는지 보려고 익명 이용 통계를 모은다. 자세한 설명과 분석 방법은 `docs/analytics.md`.

| 항목 | 값 |
|---|---|
| 사람 구분 | `vid`: 브라우저에서 한 번 만들어 localStorage에 두는 무작위 32자리 16진수. `sid`: 접속마다 새로 만드는 무작위 번호. IP, 세례명, 얼굴 그림과 연결하지 않음 |
| 끄기 | 입장 화면의 "이용 통계 보내지 않기"를 고르면 이 브라우저에서는 아무것도 보내지 않음 |
| 메시지 | `{ "type": "track", "vid": "…", "sid": "…", "events": [{ "type": "travel", "p": { "to": "nave" } }] }`. 답 없음. 5초마다 또는 15개가 쌓이면 보냄. 한 메시지 15개까지(2KB 안) |
| 페이지를 닫을 때 | WebSocket이 먼저 끊기므로 남은 것은 `POST /api/track`(본문은 위 메시지에서 `type`만 뺀 것, `text/plain`)를 `navigator.sendBeacon`으로. 허용 Origin만 받고 항상 204 |
| 이벤트 | `session_start`(src, dev, inapp, first), `intro_done`(look), `enter_hall`, `first_move`(sec, by), `joystick`(on), `place_enter`(place), `travel`(to), `booth_enter`(booth), `booth_full`, `go_confess`, `first_guide`(act), `confess_submit`(persona, kind, cat, caution, len, sample), `answer_done`(persona, cat, grade), `card_share`(persona, cat, grade), `go_pray`(persona, cat, grade), `history_open`(n), `history_card`(persona, cat, grade), `booth_leave`(sec, n), `emote`(id), `sit`(place), `candle`, `offering`, `font`, `pigeon`, `inquiry`, `face_saved`(src), `face_import`, `look_change`(rgb), `rename`, `channel_switch`, `idle_kick`(place), `session_end`(sec, place) |
| 값 | 짧은 id(영소문자, 숫자, 밑줄 24자까지), 0과 1, 0..86400 정수만. 목록에 없는 이벤트와 키, 형식이 다른 값은 서버가 버림. 고해 원문은 보내지 않고 답변 엔진이 고른 카테고리 id만. 위기 답변(`kind: safety`)은 어떤 위기였는지도 남기지 않음 |
| 한도 | 접속 하나당 분당 120개, beacon은 서버 전체 분당 3000개, Nginx에서 IP당 초당 2회 |
