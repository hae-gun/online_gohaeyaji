# 고해야지 (gohaeyaji)

> 공부해야지, 운동해야지, 그리고 고해야지.

An online confessional for the promises you broke today.

오늘도 지키지 못한 다짐을 털어놓는 온라인 고해소입니다. 성당 앞마당을 걸어 성당 안으로 들어가 초를 켜고, 고해소 방에서 빈 고해소 문을 열면 신부님이 성호경을 긋고 고해를 들은 뒤 진지한 얼굴로 조금 웃긴 보속을 내려줍니다. 같은 시간에 들어온 다른 사람들도 함께 보입니다.

- 밤새 쇼츠를 봤다면: "오늘 밤은 휴대폰을 팔이 닿지 않는 곳에 두고 주무십시오."
- 배달을 또 시켰다면: "배달비가 음식값을 넘는 순간, 그것은 식사가 아니라 기부입니다."

**바로가기:** https://gohaeyaji.com

> 이 서비스는 실제 고해성사가 아닌 패러디입니다. 웃음의 대상은 언제나 고해하는 사람의 일상이며, 천주교의 성사와 신앙을 존중합니다.

## 할 수 있는 것

| 장소 | 내용 |
|---|---|
| 앞마당 | 분수대 광장, 벤치에 앉기, 비둘기 모이 주기(먹는 동안은 가까이 가도 덜 도망감) |
| 성당 둘레길, 산책로 | 성당을 한 바퀴 도는 길, 숲을 지나 이벤트 광장까지 이어지는 두 갈래 산책로 |
| 이벤트 광장 | 무대와 현수막, 줄전구가 있는 큰 광장. 수능, 연말 같은 행사 때 현수막을 바꿔 사용 |
| 성당 안 | 초 켜기(3분 동안 타오름), 봉헌하기, 성수 찍고 성호 긋기, 장의자에 앉기 |
| 고해소 방 | 고해소 21칸(왼쪽, 정면, 오른쪽 벽에 7칸씩), 가운데 "신께 알리기" 함(사이트 문의) |
| 고해소 안 | 신부님 네 분(각자 다른 목소리와 말투), 고해와 보속, 마음에 안 드는 답은 동의를 받아 "답변 개선함"으로 보내기 |

어디서나:
- 다른 사람의 캐릭터와 세례명이 보이고, 동작(기도, 성호경, 만세, 꾸벅꾸벅)도 함께 보입니다. 앉은 채로도 동작할 수 있습니다
- 32x32 도트로 내 얼굴을 직접 그릴 수 있습니다. 기본 다섯 색에 원하는 색을 8가지까지 더할 수 있고, 부적절한 그림은 신고로 내려갑니다
- 한 채널은 60명. 차면 새 채널이 열리고, 원하는 채널로 옮길 수 있습니다. 빈 채널은 5분 뒤 닫힙니다
- 조작: WASD 이동, 드래그로 시점 회전, 휠 또는 두 손가락으로 확대, V로 1인칭, E로 상호작용, 화면을 클릭하거나 탭하면 그곳으로 걸어감. 한글 입력 상태에서도 동작합니다

## 왜 만들었나

바이럴 서비스는 언제 트래픽이 몰릴지 모릅니다. 이 프로젝트의 목표는 재미있는 서비스를 만드는 것과 함께, 한정된 자원(고해소 21칸)에 사람이 동시에 몰리는 상황을 직접 설계하고 측정해 보는 것입니다.

- 두 사람이 같은 순간 같은 고해소 문을 열어도 한 명만 들어가야 한다 (Redis Lua로 원자적 점유)
- 탭을 닫거나 잠수를 타면 자리는 다른 사람에게 돌아가야 한다 (임대 시간과 하트비트)
- 채널이 꽉 차도 서비스는 무너지지 않아야 한다 (채널 자동 배정, 빈 채널 회수)
- 수십 명이 움직여도 메시지가 폭증하지 않아야 한다 (위치는 200ms 단위로 묶어서 전송)
- 답변 분석 서버가 죽어도 신부님은 대답해야 한다

## 아키텍처

```
브라우저 ── 정적 파일 ─────────────▶ GitHub Pages
   │
   └─ wss://api.gohaeyaji.com/ws ─▶ Nginx (TLS, IP당 연결과 요청 제한)
                                      │
                                      ▼
                               realtime-server (Spring Boot 3.3, Java 21, 가상 스레드)
                                      │  점유 잠금, 채널, 신고, 문의 (Lua 스크립트)
                                      ▼
                                    Redis

ops 서버: Prometheus, Grafana ◀── 서버 지표(node_exporter), Spring 지표(/actuator/prometheus)
```

- 서버 두 대(Rocky Linux): app 서버(Nginx, realtime-server, Redis), ops 서버(모니터링)
- 위치 정보는 서버 메모리에만 있고, 고해소 점유와 채널 인원처럼 여러 사람이 다투는 상태는 Redis에 있습니다
- 답변 엔진은 아직 브라우저에서 돕니다(서버 이전은 로드맵)

## 실행 (로컬)

```bash
# 프론트만, 서버 없이 (브라우저 안 시뮬레이션)
cd frontend && npm install && npm run dev          # http://localhost:5173  (?sim=1 이면 가짜 점유 켜짐)

# 실시간 서버까지
cd backend && docker compose up -d redis
cd realtime-server && ./gradlew bootRun            # ws://localhost:8080/ws
cd ../../frontend && npm run dev:server            # 로컬 서버에 연결

# 테스트 (Docker 필요)
cd backend/realtime-server && ./gradlew test
```

관리자 페이지는 `backend/.env`에 `ADMIN_PASSWORD`를 넣었을 때만 열립니다(`backend/.env.example` 참고). 없으면 404입니다.

## 배포

**프론트 (GitHub Pages):** `main`에 `frontend/` 변경이 푸시되면 GitHub Actions가 빌드해서 배포합니다(`.github/workflows/deploy-pages.yml`). 빌드할 때 `VITE_REALTIME_URL=wss://api.gohaeyaji.com/ws`로 실서버에 연결됩니다.

**서버:** 맥에서 커밋한 뒤 `ssh <app 서버> gohae-deploy`. 변경이 있으면 다시 빌드하고, 응답 확인에 실패하면 이전 커밋으로 되돌립니다. 서버 초기 설정, 도메인과 인증서, 모니터링은 [`infra/README.md`](infra/README.md)에 있습니다.

## 답변 데이터

답변 문구와 금지어는 코드와 분리된 데이터 파일이고, 실제 파일은 git에 올리지 않습니다. `frontend/public/data/` 안의 JSON은 `*.sample.json`을 빼고 모두 `.gitignore` 대상입니다.

| 실제 파일 (git 제외) | 공개 샘플 | 용도 |
|---|---|---|
| `answers.json` | `answers.sample.json` | 카테고리 키워드와 답변 문구 |
| `safety.json` | `safety.sample.json` | 위기 키워드. 걸리면 농담을 끄고 상담 창구 안내 |
| `blocked.json` | `blocked.sample.json` | 금지어(욕설, 비하). 걸리면 보속 없이 안내 문구만. 서버도 세례명 검사에 사용 |

실제 파일이 없으면 샘플로 동작하므로, 레포를 받은 사람도 바로 실행해 볼 수 있습니다. 검사 순서는 위기 키워드, 금지어, 답변 순이고, 위기 키워드는 데이터 파일을 하나도 못 불러와도 동작하도록 엔진 안에 최소한이 들어 있습니다.

배포 사이트에는 GitHub Secrets로 넣습니다. Secret 하나에 48KB까지라 압축해서 넣고, 그래도 크면 여러 개로 나눕니다(`scripts/set-data-secrets.sh`).

**답변을 늘려 가는 흐름 (하루 한 번):**
1. 사용자가 동의하고 보낸 고해가 관리자 페이지의 "답변 개선함"에 모임
2. 관리자 페이지에서 AI에 넘길 내용을 만들어 새 키워드와 문구를 받음
3. `node scripts/apply-answer-patch.mjs patch.json` 으로 검사하고 반영(이전 파일은 자동 백업)
4. `scripts/set-data-secrets.sh answers --deploy` 로 배포

> 지금은 답변 엔진이 브라우저에서 돌기 때문에, 배포된 사이트에서는 `/data/answers.json` 주소로 누구나 파일을 열어볼 수 있습니다. git에서 빼는 것은 레포 공개 시의 스포일러만 막습니다. 완전히 숨기려면 답변 엔진을 서버로 옮겨야 합니다(로드맵).

답변 원칙:

1. 웃음의 대상은 고해하는 사람의 일상이지, 신이나 성사가 아니다
2. 성경 구절이나 기도문을 비틀어 쓰지 않는다
3. "죄를 사하노라" 같은 사죄 선언을 흉내 내지 않고 보속만 준다
4. 사용자가 쓴 말을 그대로 따라 하지 않는다. 사전에 있는 키워드만 답변에 들어간다
5. 위기 신호가 보이면 농담을 끄고 도움받을 곳을 안내한다

## 개인정보

- **고해 내용:** 서버에 저장하지 않습니다. 고해 기록은 사용자의 브라우저(localStorage)에만 남고 언제든 지울 수 있습니다
- **답변 개선함:** 사용자가 직접 동의하고 보낸 고해만 저장합니다. 전화번호와 이메일은 보내기 전에 가려지고, 30일 뒤 자동으로 지워집니다
- **신께 알리기(문의):** 내용만 저장하고 IP는 남기지 않습니다. 도배 방지는 IP의 해시로 1시간만 셉니다
- **얼굴 신고:** 악용 대응을 위해 신고한 사람과 신고된 사람의 IP를 그림별로 7일 보관합니다
- **위치와 접속 정보:** 서버 메모리에만 있고, 접속을 끊으면 사라집니다
